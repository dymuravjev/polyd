# POLYD — Театр процесса

Текущая редакция: 23 ноября 2026, исправления интерфейса и подготовка по требованиям Notion.

GitHub: https://github.com/dymuravjev/polyd. Демонстрация публикуется GitHub Actions из main. Команда `node scripts/build-pages.mjs` создаёт отдельную .pages-dist под путь /polyd/, без PHP и закрытых настроек, с noindex и явным демонстрационным поведением форм. Проверка: `node scripts/check-pages.mjs`. Сборка public предназначена для обычного хостинга с PHP и сохраняет рабочий серверный сценарий.

Репозиторий содержит всю текущую реализацию, исходные изображения, локальные библиотеки, PHP-обработчик, пример конфигурации и инструменты сборки. Локальные снимки Notion, журналы, тестовые файлы, закрытые настройки и архивы прежних версий в публичный репозиторий не включаются. Ссылки ниже на audit/ и qa/ относятся к локальным материалам проекта.

Запуск: npm run build, npm run check, npm run dev. Локальный адрес — http://127.0.0.1:4173/. Сборка создаёт public; загрузка его содержимого на Apache не требует Node или Python. Для начальной подготовки изменённых PNG используется scripts/prepare-images.py и Pillow, затем выполняется сборка.

Главная, самостоятельный FAQ, карта сайта, страницы документов и ошибки оформлены в общей системе. FAQ содержит 31 вопрос: Важное — 4, Подбор — 10, Проектирование — 9, Эксплуатация — 8. Количество определяется содержанием. Числа генерируются из единого src/shared/faq-content.json.

Карта файлов — [FILE_STRUCTURE.md](FILE_STRUCTURE.md). Порядок запуска — [docs/launch-requirements.md](docs/launch-requirements.md). Подключения и права — [docs/integrations-and-rights.md](docs/integrations-and-rights.md). Проверка — [audit/requirements-matrix-2026-11-23.md](audit/requirements-matrix-2026-11-23.md); краткий результат — [docs/revision-requirements-2026-11-23.md](docs/revision-requirements-2026-11-23.md).

Форма и обратный звонок отправляются через PHP/PHPMailer 7.2.0; автоматического открытия почтовой программы нет. К задаче можно прикрепить до 3 файлов PDF/DOCX/XLSX/JPG/PNG: до 5 МБ каждый, до 10 МБ суммарно. Ограничения проверяются в браузере и PHP, тип — также по содержимому. При ошибке поля и вложения остаются в открытой форме. PHP 8.4.28 проверен переносимым официальным комплектом: 15 сценариев с локальным SMTP-приёмником, включая MIME-вложения, ограничения, согласие и отсутствие повторной отправки. Рабочий SMTP заказчика не настроен, внешняя доставка не проверена.

Политика и согласие остаются проектами для утверждения оператором. С dosings.ru взяты опубликованные название и контактный адрес компании; они показаны в футере вместо продуктового текста. Юридический адрес, ИНН/ОГРН, срок хранения и архивный BCC не выдуманы. legalApproved выключен; включение SMTP контролируется только enabled в закрытой настройке, а не выбором другого сценария в браузере. Пароли вводятся на хостинге только в forms/private/config.php. Сборка не перезаписывает существующий файл.

Последние изменения: [docs/contact-revision-2026-11-23.md](docs/contact-revision-2026-11-23.md). Подтверждение PHP — qa/php-mail-check.json. Кнопка «Обсудить задачу» закреплена на экране, мягко пульсирует и скрывается у самой формы и футера. В шапке указан телефон. «Информация» разделена на две колонки; Intellect отделён тонкой линией на общем фоне.

На всех основных страницах и ошибках общий футер DOSINGS × Intellect. Интерактивная модель сохранена как необязательный отдельный ресурс; при встраивании её служебный футер скрывается, самостоятельный просмотр содержит футер. Это объясняющая модель и иллюстративные сцены, не утверждённая инженерная документация.

HTTP-проверка: node scripts/http-check.mjs при запущенном локальном сервере. Проверены ответы 200, 301, 403 и 404, сохранение параметров, запрет выдачи закрытых файлов, сжатие и заголовки в локальном Node-просмотре. На реальном Apache требуется повторная проверка ErrorDocument, HTTPS и PHP. Сервер предпросмотра закрывает индексацию заголовком X-Robots-Tag; публичные robots.txt и sitemap.xml подготовлены под рабочий домен, который не изменялся.

Текущая версия не объявлена полностью соответствующей 626 требованиям. В матрице отдельно указаны выполненные, неприменимые, нарушенные и непроверенные пункты. Архивные материалы до перестройки остаются в docs/history и releases, исходные проектные версии выше этой папки сохранены. В Notion ничего не записывалось.
